# DedupEngine 模块功能点

## 1. 模块概述
DedupEngine 是微内核的基础服务模块，负责**检测和折叠重复内容**，以减少 token 数量。它提供多种去重策略：行级去重、堆栈帧去重、路径去重、模式去重等。插件在压缩过程中调用 DedupEngine 的方法，将可能需要去重的文本片段传入，引擎返回折叠后的表示（如添加重复次数标记 `(xN)` 或生成 `Repeat` Token）。去重操作必须可逆，即折叠后的结果能够通过重复次数准确还原原始内容。

DedupEngine 不直接处理文本，而是作为工具供插件使用，保持无状态（或轻量状态），以便多个切片独立处理。

## 2. 数据结构
```rust
use std::collections::HashMap;

/// 去重结果
#[derive(Debug, Clone)]
pub struct DedupResult {
    pub compressed: String,   // 折叠后的文本（含重复标记）
    pub count: usize,          // 实际重复次数
    // 也可以返回 Token 流，但 MVP 阶段先用文本简化
}

/// 去重引擎配置
#[derive(Clone)]
pub struct DedupConfig {
    pub line_threshold: usize,      // 行级去重触发阈值（例如重复次数≥2）
    pub stack_frame_threshold: usize,
    pub path_threshold: usize,
    pub pattern_threshold: usize,
}

/// 去重引擎主结构
pub struct DedupEngine {
    config: DedupConfig,
    // 可选的跨切片缓存，但 MVP 阶段保持无状态
}

/// 用于堆栈帧去重的结构化表示（可选）
struct StackFrame {
    class: String,
    method: String,
    file: String,
    line: u32,
}
```

## 3. MVP 功能点清单

### 3.1 初始化引擎
- **功能描述**：创建 DedupEngine 实例，接受配置。
- **函数签名**：`pub fn new(config: DedupConfig) -> Self`
- **调用者**：CompressionPipeline 初始化时。
- **被调用者**：无。
- **依赖**：无。
- **测试要点**：配置正确保存。
- **优先级**：MVP

### 3.2 行级去重
- **功能描述**：检测输入文本中连续重复的行，折叠为一行加重复次数。例如三行连续的 `warning: unused variable` 折叠为 `warning: unused variable (x3)`。支持自定义重复次数阈值（例如 ≥2 次才折叠）。
- **函数签名**：`pub fn dedup_line(&self, text: &str) -> Option<DedupResult>`
- **调用者**：插件（如 gcc_log 插件，当处理多行日志时）。
- **被调用者**：内部扫描换行符，统计连续相同行。
- **依赖**：无。
- **测试要点**：
  - 连续重复行 → 正确折叠并返回次数。
  - 非重复行 → 返回 None。
  - 重复次数低于阈值 → 返回 None。
  - 空输入 → 返回 None。
- **优先级**：MVP

### 3.3 堆栈帧去重
- **功能描述**：检测 Java/Python 等堆栈中连续重复的帧，折叠为一行加重复次数。例如堆栈中连续出现三次相同帧，折叠为 `at com.example.Class.method(File.java:10) (x3)`。
- **函数签名**：`pub fn dedup_stack_frame(&self, text: &str) -> Option<DedupResult>`
- **调用者**：JavaStackPlugin。
- **被调用者**：内部解析堆栈行，比较帧内容（可忽略行号差异？需要定义相同帧的判断标准，例如类名和方法名相同即视为重复，行号可忽略或保留第一次的行号）。
- **依赖**：可能需要正则或简单字符串比较。
- **测试要点**：
  - 连续相同帧 → 折叠。
  - 帧内容相同但行号不同 → 根据配置决定是否视为重复（MVP 可简单视为重复）。
  - 不连续的重复帧 → 不折叠。
- **优先级**：MVP（可简化实现，复用行级去重，但为体现语义可独立）

### 3.4 路径去重
- **功能描述**：检测文本中重复出现的路径，折叠为单一路径加重复次数。例如连续多行都包含相同路径，可折叠为一行带次数。注意路径可能被其他文本包围，需要更精细的识别，MVP 阶段可先不实现或简化。
- **函数签名**：`pub fn dedup_path(&self, text: &str) -> Option<DedupResult>`
- **调用者**：gcc_log 插件等。
- **被调用者**：可能需要正则提取路径，然后比较。
- **测试要点**：待定。
- **优先级**：未来（MVP 可暂缓）

### 3.5 模式去重（正则模式）
- **功能描述**：根据用户定义的正则模式，检测连续重复的片段并折叠。例如重复的 JSON 键值对、重复的 HTML 标签块等。
- **函数签名**：`pub fn dedup_pattern(&self, text: &str, pattern: &Regex) -> Option<DedupResult>`
- **调用者**：需要自定义去重的插件。
- **依赖**：`regex`。
- **测试要点**：正确识别连续重复的匹配片段。
- **优先级**：未来

### 3.6 重置状态（如果引擎有跨切片缓存）
- **功能描述**：当开始处理新的文件或切片流时，重置内部缓存，避免跨文件误判。
- **函数签名**：`pub fn reset(&mut self)`
- **调用者**：CompressionPipeline 在开始新文件前调用。
- **测试要点**：调用后状态清空。
- **优先级**：MVP（若实现跨切片缓存则需要）

## 4. 未来功能点清单（待定）

### 4.1 跨切片去重
- **功能描述**：缓存之前切片的重复信息，用于检测跨切片的重复行（如整个文件中多次出现的相同日志行），进一步提高压缩率。
- **优先级**：未来

### 4.2 自适应阈值
- **功能描述**：根据文本长度动态调整重复阈值，避免过度折叠。
- **优先级**：未来

### 4.3 语义去重（基于 embedding）
- **功能描述**：检测语义相似而非完全相同的行（如错误消息模板相同但参数不同），进行泛化折叠。
- **优先级**：未来

---

## 5. 与其它模块的交互
- **调用者**：插件的 `compress` 方法通过可变引用获取 DedupEngine，并调用相应去重方法。插件负责将去重结果合并到 Token 流中。
- **输出**：返回 `DedupResult`，插件可根据需要将其转换为 `Token::Repeat` 或直接插入文本标记。
- **状态管理**：若引擎有内部缓存，CompressionPipeline 应在每个文件开始前调用 `reset()`。

## 6. 待办与注意事项
- **去重粒度**：行级去重最简单，堆栈帧去重需要解析帧结构。MVP 阶段可先实现行级去重，堆栈帧去重复用行级去重（因为堆栈帧通常每行一个帧），但要注意行号不同时是否视为重复。建议堆栈帧去重忽略行号，只比较类名和方法名。
- **重复标记格式**：统一采用 ` (xN)` 后缀，便于识别和还原。
- **可逆性**：还原时需根据重复次数展开。若使用 `(xN)` 标记，还原时需解析并复制 N 次。
- **性能**：去重操作应使用哈希表记录最近出现的行，避免 O(n²) 比较。
- **错误处理**：去重失败应返回 None，由插件决定是否继续。
