## 🔧 四、关键数据结构的流转（Rust 视角）

```rust
阶段1: 原始文本
    ↓
阶段2: StreamReader 输出 SliceInput
struct SliceInput<'a> {
    raw: &'a str,
    offset: usize,
    line_number: usize,
    file_metadata: Option<&'a FileMetadata>, 
}
    ↓
阶段3: TextSlicer 输出 Slice (显式生命周期绑定以解除借用冲突)
struct Slice<'a> {
    id: u64,
    text: &'a str,
    slice_type: SliceType,        // 初步类型（可选）
    offset: usize,
    line_start: usize,
    line_end: usize,
    file_metadata: Option<&'a FileMetadata>, // 可选携带
}
    ↓
阶段4: ContentAnalyzer 分析，输出 AnalysisResult
struct AnalysisResult {
    slice_type: SliceType,        // 最终推断类型
    confidence: f32,
    details: Option<String>,
}
    ↓
阶段5: PluginDispatcher 根据 AnalysisResult 选择 Plugin
trait Plugin {
    fn detect(&self, slice: &Slice) -> DetectionResult; // 可能仍调用，但置信度可融合
    fn compress(&self, slice: &Slice, dict_engine: &mut DictionaryEngine, dedup_engine: &mut DedupEngine) -> CompressResult;
}
    ↓
阶段6: Compression Pipeline 生成 Token 流
enum Token<'a> {
    Text(Cow<'a, str>),
    DictRef(Cow<'a, str>),
    Repeat { token: Box<Token<'a>>, count: usize },
    Marker { kind: MarkerKind, value: Cow<'a, str> },
    Diff { base: Cow<'a, str>, patch: Cow<'a, str> },
}
    ↓
阶段7: 最终输出 CompressionOutput
struct CompressionOutput {
    tokens: Vec<Token>,
    dictionary: Dictionary,
    metadata: CompressionMetadata, // 包含原始顺序信息等
}
    ↓
阶段8: Rehydration Pipeline 还原
fn rehydrate_tokens(tokens: &[Token], dict: &Dictionary, order_info: Option<&OrderInfo>) -> String;
```

## 🧠 五、核心流程的文字描述（确保你没丢）

1. **输入**：用户通过 VSCode/CLI/CI/CD 提交原始文本（日志/堆栈/代码/混合内容）。
2. **流式读取**：StreamReader 按行或按块读取，同时获取文件元数据（路径、大小、修改时间、BOM 等），检测二进制文件，输出 `SliceInput`（零拷贝切片 + 元数据引用）。
3. **内容切片**：TextSlicer 根据策略（行/空行/缩进/标签/正则/混合）将输入拆分为 `Slice`，每个 Slice 标注初步类型，并携带文件元数据（可选）。
4. **内容分析**：ContentAnalyzer 对每个 Slice 进行精确类型识别，融合规则识别（关键词/正则）与可选的 embedding 置信度，输出 `AnalysisResult`（最终类型、置信度）。
5. **插件调度**：PluginDispatcher 根据分析结果选择最合适的插件，支持插件链（如 HTML → 去标签 → 自然语言）；若插件未注册对应类型，则 fallback 到默认插件。
6. **压缩**：选中插件的 `compress()` 执行，过程中：
   - 调用 DictionaryEngine 生成字典项（仅建立正向映射 Original -> Token 以保证压缩性能）。
   - 调用 DedupEngine 折叠重复结构（行/堆栈/路径/模式），并可选对并行日志（如 make -jN）按文件名重排序。
   - 生成 Token 流（或可选 AST），并记录重排序信息（用于后续还原）。
7. **合并输出**：CompressionPipeline 将所有 Slice 的 Token 流、字典、元数据（含压缩率、重排序信息）合并为 `CompressionOutput`。
8. **还原**：RehydrationPipeline 接收压缩结果，直接使用 O(1) 的 Dictionary 快照进行 Token 解析、Repeat 展开、AST 重建、插件 `decompress()` 恢复原始文本；若包含重排序信息，则恢复原始顺序。
9. **错误隔离**：任何插件 panic 或超时，SafeExecutor 捕获并 fallback，不影响主流程。
10. **指标收集**：MetricsCollector 记录各模块耗时、插件调用次数、错误日志，供优化和监控。

## ✅ 总结

修改后的数据流图已包含：
- **内容分析引擎**
- **文件元数据获取**（StreamReader）
- **二进制检测**
- **混合内容处理**（插件链）
- **并行日志重排序**（在 DedupEngine 中增加 `reorder_log` 方法）
- **可逆压缩与还原**（字典、去重、AST）
- **错误隔离与指标收集**

所有关键需求均已覆盖，现在可以基于此图逐模块细化功能点。
