# P3-210 privacy 词表豁免设计稿（TokenSlim · 2026-09-11）

## 一、背景与动机

P3-209 将占位符短化（`[TS_*]` → `[UR]` 等）后，用户真实 `ls -l` 样本仍 107 tok > 原文 96 tok
（设计稿 §七 实证：被掩码短词 `wiimu` 本身 ≈1 tok < 任何占位符 ≥2 tok，**短词掩码的绝对膨胀
是安全功能固有成本**）。用户提出词表思路：**词表内的词不转换**——词表是用户对「该词不敏感」
的显式声明，豁免后替换不发生，膨胀归零。这是短化之后唯一能在短词场景真正清零膨胀的杠杆。

## 二、安全边界（两条红线，违反即否决）

1. **豁免必须是用户显式配置，压缩器绝不自动决定**。「这个词不值钱所以不脱敏」若由压缩器按
   token 成本自动跳过，等于让压缩器决定泄露什么——违反 AGENTS.md「安全 > 节省」。词表的
   语义是用户声明，责任归属清晰。
2. **豁免只作用于用户自定义规则，内置凭证规则永不豁免**。即便词表里写着整枚 AWS Key，
   内置规则照样替换（有专门契约测试守护）。

## 三、方案（用户裁决：独立词表文件）

- 词表文件：`.tokenslim-redact-allowlist`（与规则文件 `.tokenslim-redact.toml` 同目录、同
  「一行一词」格式；`#` 注释、空行忽略；词精确匹配、区分大小写、无子串语义）。
- 豁免语义：**整体命中豁免**——自定义规则匹配到的片段**恰好等于**词表词时原样保留；
  词表词只作为更大匹配片段的子串出现时照常替换（保守侧优先）。
- 实现点：`redact_text` 中自定义规则 fold 改为闭包替换——匹配片段 ∈ 词表 → 原样，否则
  `[UR]`。内置规则（此前执行）不受影响；`BUILTIN_REDACTOR` 单例无词表。
- 探测一致性：`contains_sensitive_value` 基于 `redact_text` 与原文比较，豁免后自动视为
  未命中 → detect 不同命中 → 样本零改写直通 generic 路径。口径自动一致，无需额外处理。

## 五、验收标准

1. 词表词整体命中自定义规则 → 原样保留（含用户真实样本：6 处 `wiimu` 全豁免 → detect
   不命中 → 零改写、零膨胀，回到 96 tok 基线）；
2. 子串命中不豁免、内置规则永不豁免（契约测试）；
3. 词表文件缺失 → 空词表、行为与现状完全一致（向后兼容）；
4. 全量 lib 回归通过；机制自身输出开销 = 0（符合第一性原理第 3 问）。
