## 关键决策 (2026-06-24 下午更新)

| 决策                                 | 选择                                                                                    | 理由                                               |
| ------------------------------------ | --------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **白名单 vs 黑名单**                 | **白名单 (双向控制)**                                                                   | 未知命令**永远**走 fallback, 永不卡                |
| **白名单 (compress_whitelist) 含义** | **不是**交互式, 已知**可压缩**                                                          | → 走 plugin 压缩 (VCS/build/test)                  |
| **支持列表 (tty_support_list) 含义** | **是**交互式, **我们支持** ConPTY                                                       | → 走 ConPTY (vim/ssh/REPL/分页器/subshell)         |
| **未知命令**                         | **永远** fallback (Stdio::inherit)                                                      | **永不**卡, **最**安全                             |
| **L1 默认范围**                      | **~50 个 compress** (VCS/build/test) + **58 个 tty** (编辑器/REPL/远程/分页器/Subshell) | 覆盖 99% 已知场景                                  |
| **L2 文件**                          | `config/whitelist.toml` (覆盖**两个**清单, `[compress]` + `[tty]` 两段)                 | 单文件管两清单                                     |
| **L3 文件**                          | `~/.tokenslim-whitelist.toml` (用户目录)                                                | 同 L2 格式                                         |
| **合并优先级**                       | L3 (用户) > L2 (项目) > L1 (代码默认)                                                   | 用户**移除**优先于默认                             |
| **ConPTY 探测策略**                  | **启动时一次**探测 (`cmd /c ver` 走 ConPTY)                                             | 50ms 启动延迟, Trae 沙箱场景最差看到 1 次失败      |
| **run vs compress 入口**             | **仅** `run` mode 走 ConPTY/白名单, `compress` 永远文本压缩                             | 文本输入**永不**走交互                             |
| **v0.3.7 heuristic**                 | **整段删除** (detect_git_interactive + is_git_program)                                  | 双清单覆盖**所有**已知场景, heuristic **不再**需要 |
| **Trae IDE 沙箱**                    | ConPTY child 被沙箱 Ctrl+C 截断 (0xC000013A), **自动降级** fallback                     | 沙箱不可控, 设计容错                               |

## 背景

v0.3.7 修复了 `tokenslim run git commit` (无 -m) 在 git 交互子命令时的卡死 bug, 但**只覆盖 git**.
其他交互场景仍有 tty 切断问题, 涉及三层调用链:

```
[终端 tty]
   |
   v
[CLI run 入口] run_external_command_capture (Stdio::piped)
   |
   v
[MCP server] spawn(cli, args, { stdio: ["pipe","pipe","pipe"] })  <- Claude Code/Cursor 调
   |
   v
[CLI run 入口] (再次 Stdio::piped)
   |
   v
[外部命令] git/hg/svn/vim/htop/ssh/...
```

任何一层的 stdio = pipe 都会切断 tty, 触发卡死.

## v0.3.7 解决范围

仅修复最内层 (CLI -> 外部命令) 的 git 交互子命令, 通过启发式黑名单 + 透明 fallback 透传 stdio.

## v0.4.0 目标

**通用解: 引入 portable-pty 跨平台 tty 转发**, 一次性解决:
- 所有 VCS (git/hg/svn/jj/bzr/fossil/p4) 的交互子命令
- 所有 TUI 工具 (vim/htop/less/...)
- 所有 REPL (python/node/mysql/psql/ssh)
- MCP 客户端经 MCP server 调用的 tty 交互
- shell 注入场景 (`source <(tokenslim run ...)`)

## PoC 实际验证结果 (2026-06-24)

| 测试         | 命令                                | Trae IDE 内嵌终端 | Win+R cmd       | 结论                    |
| ------------ | ----------------------------------- | ----------------- | --------------- | ----------------------- |
| 1            | `git --version` 走 ConPTY           | exit 0xC000013A   | exit 0xC000013A | ConPTY child 被沙箱截断 |
| 2            | `cmd /c ver` 走 ConPTY              | exit 0xC000013A   | exit 0xC000013A | 同上                    |
| 3            | `git status` 走 ConPTY              | exit 0xC000013A   | exit 0xC000013A | 同上                    |
| 4            | `git log --oneline -5` 走 ConPTY    | exit 0xC000013A   | exit 0xC000013A | 同上                    |
| **5 (对照)** | `cmd /c ver` 走普通 std::process    | **exit 0**        | **exit 0**      | 沙箱**不**截普通 child  |
| **6 (对照)** | `git --version` 走普通 std::process | **exit 0**        | **exit 0**      | 同上                    |

**关键发现**:
- **Trae IDE 沙箱**只截 ConPTY 创建的子进程, **不**截普通 std::process 启动的子进程
- **普通 std::process** 跑 `cmd /c ver` 和 `git --version` 都能成功 (exit 0, 拿到输出)
- **ConPTY** 拿到的 stdout 仅 16 字节 (ConPTY 自身初始化序列 `ESC[?9001hESC[?1004h`), **child 还没输出就被 Ctrl+C 截断**
- 编译 + openpty + spawn_command + child 启动全部成功 — 失败是**外层沙箱**控制, **不是** portable-pty bug, **不是** Windows 不兼容

## 重新设计: 双清单 + 三层混合 (2026-06-24)

### 为什么**不**用 CLI flag (`--tty` / `--passthrough`)

原 Phase A 提议加 `--tty` flag 让用户显式开启. **问题**:
- 用户**每次**跑 `vim` / `ssh` / `python` 都要加 `--tty` → 易忘, 体验差
- 不知道**什么**命令需要 `--tty` → 文档负担
- 漏写就**卡死** → **不**如 fallback 自动

### 为什么**不**用单边白名单 (我**之前**的误读)

**我之前理解错的版本**: "白名单 = 走 ConPTY 的命令 (vim/ssh/REPL)".
- **问题**: 99% 命令 (ls/cat/echo/cargo/cargo build/cargo watch) 都**不**在白名单 → 全部走 fallback, **plugin 压缩** 几乎用不上
- 99% 场景下: 已知可压缩的命令 (cargo/git/npm) **不**能享受 plugin 压缩

### 为什么**用**双清单 (你**今天**纠正的版本)

**正确理解** (你的原话):
- **白名单 (compress_whitelist)** = **不是**交互式, 已知**可压缩** → plugin 压缩
- **支持列表 (tty_support_list)** = **是**交互式, **我们支持** ConPTY → ConPTY
- **未知** → fallback (Stdio::inherit, **永远**不卡)

**优势**:
- VCS/build/test 在 compress_whitelist → 享受 plugin 压缩 (vcs_git_plugin, cargo plugin, npm plugin)
- vim/ssh/REPL 在 tty_support_list → 享受 ConPTY 真交互
- 任何不在清单的命令 → fallback (Stdio::inherit), **永不**卡

### 为什么**不**用黑名单 (v0.3.7 风格)

- 未知命令**意外**卡死, **无 opt-out**
- 维护负担: 每次新发现一个卡死命令要改代码
- **不**知道"我们不支持什么会卡"

### 为什么**用**白名单 (用户洞察)

- **未知**命令**永远**走 fallback (Stdio::inherit), **永不**卡
- **白名单**走 plugin 压缩 (VCS/build/test, 已知输出可压缩)
- **支持列表**走 ConPTY 尝试真交互 (vim/ssh/REPL)
- **原则**: 我们**支持什么**自己知道 (双清单), 我们**不支持什么**不知道 → 走 fallback

## 三层双清单合并架构

| 层                   | 文件                                                                               | 位置                         | 入仓?    | 内容                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------- | ---------------------------- | -------- | --------------------------------------------------------------------------------------- |
| **L1 代码默认**      | `src/cli/commands/run.rs` 硬编码常量                                               | binary                       | N/A      | **~50 个** compress (VCS/build/test) + **58 个** tty (编辑器/REPL/远程/分页器/Subshell) |
| **L2 项目 extra**    | 新建 `config/whitelist.toml`                                                       | config/, **打包**嵌入 binary | ✅ 入仓   | 项目特定 compress + 项目特定 tty (e.g. `make watch`, `npm run dev`)                     |
| **L3 用户 override** | `~/.tokenslim-whitelist.toml` (Windows: `%USERPROFILE%\.tokenslim-whitelist.toml`) | 用户目录                     | ❌ 不入仓 | 用户**移除**默认的 + 用户**追加**自己的                                                 |

**合并优先级** (高到低): L3 (用户) > L2 (项目) > L1 (默认)
- 用户**移除** = 即使在 L1/L2 也**不**走对应路径
- 用户**追加** = 即使不在 L1/L2 **也**走对应路径

## 3 路分发 (取代原 v0.3.7 heuristic + 4 路分发)

`src/cli/commands/run.rs::run_run_mode` 改为:

```rust
fn run_run_mode(prog: &str, args: &[String], ...) -> Result {
    // 0. tokenslim 内置命令 (e.g. `tokenslim gain`)
    if is_tokenslim_builtin(prog) {
        return run_builtin(prog, args);
    }

    let lists = Whitelist::load();  // 合并 L1 + L2 (include_str!) + L3

    // 1. compress_whitelist (可压缩, 已知非交互)
    if lists.compress_matches(prog) {
        return run_with_plugin_compression(prog, args);  // vcs_git_plugin / cargo / npm ...
    }

    // 2. tty_support_list (交互式, 我们支持 ConPTY)
    if lists.tty_matches(prog) {
        if is_conpty_available() {  // 启动时一次探测, 缓存
            return run_external_command_pty(prog, args);  // 真交互
        } else {
            return run_external_command_passthrough(prog, args);  // Trae 沙箱 fallback
        }
    }

    // 3. 未知 → fallback (Stdio::inherit, 永远可用, 永不卡)
    return run_external_command_passthrough(prog, args);
}

// v0.3.7 heuristic (detect_git_interactive + is_git_program) 整段删除
// 双清单覆盖所有已知场景, heuristic 不再需要
```

## ConPTY 启动时探测

```rust
use std::sync::OnceLock;

static CONPTY_AVAILABLE: OnceLock<bool> = OnceLock::new();

pub fn is_conpty_available() -> bool {
    *CONPTY_AVAILABLE.get_or_init(|| {
        // 探测: cmd /c ver 走 ConPTY
        match run_external_command_pty_quick_probe("cmd", &["/c", "ver"], 1) {
            Ok((_, exit_code)) => exit_code == 0,
            Err(_) => false,
        }
    })
}
```

**为什么启动时一次**:
- 50ms 启动延迟可忽略
- Trae 沙箱场景下, 探测 1 次失败 = 后续所有白名单命令**自动**走 fallback, 用户无感
- 探测成功 = 真 Windows session, **所有**白名单命令享受 ConPTY 真交互
