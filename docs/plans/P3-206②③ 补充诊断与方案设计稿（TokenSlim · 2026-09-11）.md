## 二、独立实测复现（2026-09-11，真实管线口径）

方法：真实 `CompressionPipeline`（`PipelineConfig::default()` + `tokenslim::cli::get_plugins()`）+ `compress_str`，取 `1 - out_text_bytes / in_bytes`（内容口径，排除 JSON 包装层）；路由指纹取 `get_metrics().snapshot().plugin_stats`。样本取自 `.tokenslim/audit/_samples/`（登记分析所用的同一批物理文件）。

| 样本 | 输入字节 | 产物字节 | 内容 ratio | 节省 | 路由指纹（compress_calls） |
|---|---|---|---|---|---|
| `large.txt`（aws s3 ls） | 3,383,777 | 3,326,920 | **0.9832** | 1.7% | `smart_path×38`（**唯一**变换） |
| `cargo_clippy.txt` | 321,905 | 110,028 | **0.3418** | **65.8%** | `rust_go 250, json 77, shell_session 67, gcc_log 65, nodejs 14, privacy 5` |
| `cargo_test.txt` | 36,033 | 14,139 | 0.3924 | 60.8% | `rust_go 88, json 31, …` |
| `cargo_test_quiet.txt` | 56,612 | 15,824 | 0.2795 | 72.1% | `rust_go 151, …` |

**结论分歧**：
- **② 成立**：1.7% 与登记完全一致，且路由显示**只有** `smart_path` 做了路径字典化，列式结构零利用。
- **③ 不成立（已改善）**：实测节省 65.8%，与登记的「仅省 2~3%」相差一个数量级。登记数据来自 2026-09-10 的 release 二进制；此后落地的两处修复应已消除主因：
  1. 调度层**统一入口剥离 ANSI**（`dispatch_slice_sticky` 步骤 0，原先 ANSI 残留会把 `error[E`/`warning:` 前缀匹配全部打失、落到 generic_text）；
  2. `rust_go::compress_cargo_warning` 的 warning 块折叠。
  产物尾部可见 `[SUMMARY] 1 warnings, 1 notes` 与折叠后的 warning 块，`rust_go` 接管 250 个切片 → 折叠确已生效。
  ⚠️ 残余可疑点：登记口径可能是 **run 模式**（`tokenslim run`，带 PTY/ANSI 差异）；本稿为 **库级默认配置**口径。**③ 需以 run 模式复测确认**，再决定是否撤项（见 §五 待裁决 D-3）。

## 三、② 的真实根因与机会量化

`large.txt` 形态（首行是命令本身，其后为列式列出）：

```
aws s3 ls s3://wiimhome.homepage/assets/ --recursive --profile prod --region ap-southeast-1
2024-02-20 13:47:59          0 assets/
2025-10-10 19:23:28      16090 assets/001-Dm26V95j.png
2025-10-10 19:23:23      10526 assets/002-DfUlQE6T.png
```

55,664 行；**55,662 行**匹配 `YYYY-MM-DD HH:MM:SS <右对齐尺寸> <路径>`。逐列冗余量化（占总输入字节）：

| 冗余源 | 量化 | 占比 | 说明 |
|---|---|---|---|
| 尺寸列**左填充空格** | 310,251 B | **9.3%** | `%11s` 右对齐，纯填充 |
| **日期列** | 612,282 B | **18.4%** | 仅 **306 个不同日期**（top: `2026-08-17`×1591）→ 可字典化到近零 |
| **目录前缀** | ≈445 KB | **≈13%** | 路径 55,662 条全不同，但**仅 19 个不同目录前缀**，`assets/` 覆盖 55,607 行 |
| 合计可回收 | — | **≈38~40%** | 当前仅回收 1.7% |

**根因**：管线中**没有任何插件认领「列式目录清单」这一命令族**。`smart_path` 只做路径前缀字典化（`s3:$P101/assets/`），且仅作用于首行；尺寸列填充与日期列重复**无人处理**。属于**能力缺口**（缺命令族插件），而非既有插件缺陷——与 ① 的性质不同。

## 四、方案选项

| 方案 | 做法 | 切口 | 风险 | 预期收益 |
|---|---|---|---|---|
| **A 新增 `ls_listing` 插件**（专用命令族） | 新插件认领 `aws s3 ls` / `ls -l` / `ls -lh` / `gsutil ls -l` 等列式清单：① 尺寸列填充规约（`%Ns` 右对齐 → 单空格 + 数字）；② 日期列跨行字典化（重复日期 → 同前标记）；③ 目录前缀上提为行首块头（`assets/` 只出现一次）；④ ROI 门控不扩张 | 中：`src/plugins/ls_listing_plugin/**` + `mod.rs` + `config/plugins/*.json` + `samples/ls_listing_plugin/**` + showcase | 中：新插件需走完整「新增插件」审计链（`1→3→4→1`）与语义门禁 | ② ≈38% |
| **B 扩展 `smart_path`** | 在既有路径插件里加「列式尺寸/日期规约」分支 | 小 | 中：职责越界（path 插件管时间/数字列），且 `smart_path` 是压缩链高频插件，回归面大 | 同 A（但归属混乱） |
| **C 泛化列式折叠 Pass** | 在管线层做「等宽列检测 + 列字典化」通用 Pass | 中 | 高：影响所有插件产物，冻结基线全面漂移 | 覆盖 `ls`/`df`/`ps` 等一族 |

**推荐**：**A**。理由：职责清晰（命令族插件正是本项目架构取向——`vcs_*`、`cloud_log`、`web_log` 均按命令族切分）；收益明确（38% vs 1.7%）；风险可控（新插件默认不干扰既有插件路由，只要 `detect` 足够窄）；且 B 会把时间/数字列语义塞进路径插件，C 会全域漂移冻结基线。

> A 的关键约束：`detect` 必须**足够窄**，只认「≥N 行、列结构稳定、含右对齐数字列」的清单，避免与 `shell_session`（无结构终端输出兜底）抢样本。此约束应由样本负例（`ls` 之外的多行文本、`git status`、`ps aux`）在审计中守住。

## 六、测试计划

1. **边界与不扩张**：≥2KB 的列式清单必须折叠且 `out_bytes < in_bytes`；<阈值小清单不得扩张。
2. **零丢失**（语义门禁先行）：全部 55,662 条路径与尺寸数值在 `decompress` 后与原文逐条等价（或按声明的不可逆口径：路径集合与尺寸集合必须完整保留）。
3. **负例守卫**：`ps aux`、`git status`、`docker ps`、普通多行文本不得被 `ls_listing` 认领（用 `tests/pipeline_plugin_routing.rs` 的**负路由守卫**范式落地，见 ① 的 A1 结论）。
4. **物理样本**（红线 2）：`samples/ls_listing_plugin/` 放真实 `aws s3 ls` 输出（`large.txt` 裁到 ~50KB 以控仓体积），禁止手写 mock。
5. **管线级回归**：按 `tests/pipeline_plugin_routing.rs` 追加正/负路由守卫（审计路径绕过 detect，本类缺陷只能靠管线级回归发现）。
